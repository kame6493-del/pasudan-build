# 過去問の書き起こし仕様(作業者向け)

入力: work/<年>_<1|2>.json … 問番号ごとに official_answer(IPA 公式解答のカナ)、pages(ページ番号)、ocr(Windows OCR の行。誤りが多い: 間→問、ア→落ちる/了、エ→工、0→O、l→1 など)。
ページ画像: pages/<年>_<2桁ページ>.png(200dpi)。必ず Read で画像を見て、OCR ではなく画像を正とする。

出力: out/<年>_<1|2>.json … 配列。1問1オブジェクト:

{
  "no": 6,
  "q": "デジタルトランスフォーメーションに関する説明として，最も適切なものはどれか。",
  "choices": ["PCやスマートフォンなどの…こと", "…", "…", "…"],   // ア,イ,ウ,エ の順。記号は付けない
  "answer": "エ",            // official_answer をそのまま写す(自分で変えない)
  "field": "strategy",       // strategy | management | technology(下の範囲で決まる)
  "topic": "経営戦略",        // 下の一覧から1つ
  "explain": "…",           // 自分で書く解説。60〜160字。正解の理由と、紛らわしい選択肢との違い。確信が持てない所は書かない
  "terms": ["DX"],          // この問題の中心の用語(0〜3個)。一般的な名称で
  "table": [["列1","列2"],["a","b"]],   // 任意。問題文中の表を文字だけで正確に再現できる場合のみ
  "code": "…",              // 任意。擬似言語のプログラム等、等幅で正確に再現できる場合のみ(改行は \n、字下げは全角空白でなく半角空白2個)
  "exclude": "図が必要"       // 任意。図・グラフ・画像・複雑な表・線の入った図(E-R図、ネットワーク図、グラフ、アローダイアグラム、フローチャート等)が解答に必要で文字だけでは正しく再現できない問題は exclude に理由を書き、q と choices は入れられる範囲でよい
}

本文の決まり:
- 句読点は原文どおり全角の「，」「。」を使う(IPA の表記)。英数字は半角。
- 選択肢が「a，b」のような組合せの表(列見出し付き)の場合は、choices を「a: ○○ / b: △△」のように見出しを付けて1行にする。
- 問題文の中の下線・空欄は［ a ］のように書く。
- 「問1から問34まではストラテジ系」のような区切り文、ページ番号、注意書きは入れない。
- 擬似言語の共通の説明ページや表計算ソフトの機能説明ページは不要。表計算・擬似言語の問題は、その説明がないと解けないなら exclude。
- answer は official_answer を必ず写す。もし読んだ内容と公式解答が明らかに矛盾する(選択肢の順番を読み違えた等)と思ったら、画像を見直して choices の順番を直すこと。answer は変えない。どうしても合わない場合は "note" に書く。

field の範囲:
- 2026r08: 問1〜34 strategy / 問35〜54 management / 問55〜100 technology
- 2025r07, 2024r06: 問1〜35 strategy / 問36〜55 management / 問56〜100 technology

topic の一覧(field ごとにこの10個から選ぶ。完全に同じ文字列で):
- strategy: 企業と組織 / 会計・財務 / 知的財産権 / 法律・標準化 / 経営戦略 / マーケティング / 技術戦略 / ビジネスインダストリ / システム戦略 / システム企画
- management: システム開発 / 開発手法 / プロジェクトの計画 / スケジュールとコスト / 品質・リスク・人 / サービスマネジメント / 運用とサービスデスク / ファシリティと可用性 / システム監査 / 内部統制・ガバナンス
- technology: 基礎理論・AI / アルゴリズム・プログラミング / コンピュータ構成 / システム構成・信頼性 / ソフトウェア・OS / 情報デザイン・メディア / データベース / ネットワーク / セキュリティの脅威 / セキュリティ対策

解説の書き方: です・ます調。短く正確に。「正解は○」で始めない(画面に正解は別に出る)。例:「SLA はサービスの提供者と利用者が、稼働率や応答時間などの品質の目標を合意した文書です。RPA はパソコン作業の自動化、ERP は基幹業務の統合、CRM は顧客との関係管理です。」
